# 사내 위키 페이지 기획

## 목적

팀에서 자주 사용하는 업무 도구와 문서 링크를 한곳에 모아, 팀원이 필요한 자료를 빠르게 찾게 한다.

## 사용자와 사용 상황

- 기존 팀원: 업무 중 필요한 문서와 도구를 찾을 때 사용한다.
- 신규 팀원: 입사 초기에 자주 쓰는 자료와 담당자를 확인할 때 사용한다.
- 문서 위치를 모르는 사람: 메신저에 다시 질문하기 전에 확인한다.

## 해결할 문제

- 같은 문서의 위치를 반복해서 묻는 문제
- 링크가 메신저와 개인 북마크에 흩어진 문제
- 링크 이름만으로 사용 상황을 판단하기 어려운 문제
- 문서 문제를 누구에게 문의해야 할지 모르는 문제
- 오래된 정보인지 판단하기 어려운 문제

## 기능과 필요한 이유

### 카테고리별 분류

링크가 많아져도 필요한 자료를 빠르게 찾기 위해 필요하다.

### 링크 이름

클릭하기 전에 어떤 도구나 문서인지 판단하기 위해 필요하다.

### 설명과 사용 상황

현재 찾는 정보가 맞는지 링크를 열기 전에 확인하기 위해 필요하다.

### 클릭 가능한 주소

위키에서 필요한 페이지로 바로 이동하기 위해 필요하다.

### 담당자 또는 문의처

접근 권한이나 내용에 문제가 있을 때 바로 문의하기 위해 필요하다.

### 마지막 업데이트 날짜

현재도 신뢰할 수 있는 정보인지 판단하기 위해 필요하다.

### 추가 문의 안내

위키에서 찾지 못한 정보가 있을 때 다음 행동을 알려주기 위해 필요하다.

### 검색

링크 이름, 설명, 카테고리 이름을 기준으로 필요한 항목을 빠르게 찾기 위해 필요하다. 검색 결과가 없으면 다음 행동을 안내한다.

## 이번에 만들 범위

- 한 페이지에서 전체 카테고리 표시
- 카테고리별 카드 구성
- 링크 이름, 설명, 주소, 문의처, 업데이트 날짜 표시
- 페이지 상단 검색창
- 검색어가 포함된 링크와 카테고리 필터링
- 검색어 삭제 시 전체 항목 복원
- 화면 데이터는 `wiki-data.json`으로 분리
- 내용 변경은 AI에게 `wiki-data.json` 수정을 요청
- PC와 모바일 화면 대응
- GitHub와 Vercel을 연결한 웹 배포

## 이번에 만들지 않는 것

- 로그인과 사용자 권한
- 여러 사람의 동시 편집
- 데이터베이스
- 관리자 페이지

로그인 기능이 없으므로 실제 사내 정보나 비공개 주소는 사용하지 않는다.

## 기술 스택

- 화면 구조: HTML
- 디자인과 반응형 화면: CSS
- JSON 데이터 표시와 검색: 바닐라 JavaScript
- 화면 데이터: `wiki-data.json`
- 기획 판단: `wiki-plan.md`
- 로컬 확인: AI가 실행하는 간단한 로컬 웹 서버
- 변경 기록과 원격 저장: Git과 GitHub 비공개 저장소
- 배포: GitHub 저장소와 연결한 Vercel 정적 배포

React, Next.js, 데이터베이스, 별도 백엔드, 로그인은 사용하지 않는다. 여러 사용자가 웹 화면에서 직접 내용을 수정하거나 사용자별 권한이 필요해질 때만 백엔드를 검토한다.

## 완료 기준

- 다섯 개 카테고리가 한눈에 구분된다.
- 모든 항목에 링크 이름과 사용 이유가 표시된다.
- 링크를 눌러 예시 주소로 이동할 수 있다.
- 문의처와 업데이트 날짜가 표시된다.
- 링크 이름, 설명, 카테고리 이름으로 검색할 수 있다.
- 검색어를 지우면 전체 항목이 다시 표시된다.
- 검색 결과가 없을 때 안내 문구가 표시된다.
- PC와 모바일에서 글자와 카드가 잘리지 않는다.
- `wiki-data.json`을 변경하면 화면에도 같은 내용이 표시된다.
- 배포된 웹 주소를 다른 사람의 브라우저에서 열 수 있다.
